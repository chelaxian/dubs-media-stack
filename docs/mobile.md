# Мобильные и ТВ-обёртки

Мобильные приложения — **необязательная** часть: сервер и панель полностью
работают в обычном браузере. Нативное приложение не нужно для запуска стека.

## Что здесь есть и чего здесь нет

В репозитории лежат **исходники собственных обёрток Dubs** (`mobile/`):

- **Android 9+** (`minSdk 28`, `compileSdk`/`targetSdk` 36, Java 17, AGP 8.10.1):
  WebView-обёртка панели — package **`app.dubs.panel`** (v1.2.0, versionCode 12,
  `mobile/android/app`) и вариант для **Android TV** — package
  **`app.dubs.panel.tv`** (v1.4.0-tv, versionCode 7, `mobile/android/tv`;
  режим навигации с пульта — `mobile/server/tv.css` подключается панелью
  как `dubs-tv`).
- **iOS 17+** (deployment target 17.0, bundle **`app.dubs.panel`**, v1.2.0):
  минимальная обёртка (`mobile/ios`, проект XcodeGen — `project.yml`;
  подписывание в проекте отключено — `CODE_SIGNING_ALLOWED=NO` — установка
  в контексте TrollStore, не App Store).

Обёртки — это тонкие WebView-шеллы: открывают **ваш** HTTPS-адрес панели,
добавляют в User-Agent маркер `DubsNative/1.2 Android` (+ `DubsTV/1.0` для ТВ)
и открывают deeplink-переходы к эпизодам. Панель по маркеру даёт обёртке
долгую сессию (persistent cookie) и показывает ТВ-режим.

**Чего здесь нет**: сторонние клиенты (Findroid, Swiftfin, Fladder, Streamyfin,
Infuse) **не написаны с нуля в этом проекте, не бандлятся, не компилируются и
не подписываются** в этом репозитории. Их происхождение и лицензии — по
апстрим-ссылкам в [THIRD_PARTY.md](../THIRD_PARTY.md). Готовые APK/IPA из этого
репозитория не распространяются; проверок на физических устройствах не
заявляется. Секретов подписывания в репозитории нет: release-сборка Android
берёт keystore и пароли из переменных окружения `DUBS_KEYSTORE` /
`DUBS_SIGNING_PASSWORD` (см. `build.gradle`).

## Deeplink-переходы к эпизодам

Кнопка «смотреть» на панели возвращает бессерверные ссылки (без кредов):

| Клиент | Ссылка | Примечание |
|---|---|---|
| Findroid (Android) | `jellyfin://item/<uuid>` | переход к серии; Android-обёртка пробует сначала свои варианты package (`dev.jdtech.jellyfin.dubs[.tv]`), затем апстримный `dev.jdtech.jellyfin` |
| Swiftfin (iOS/tvOS) | `swiftfin://<serverId>/<userId>/item/<itemId>` | в Info.plist — `LSApplicationQueriesSchemes` |
| Fladder | `fladder://details?id=…&userId=…&serverId=…` | |
| Streamyfin (iOS) | `streamyfin://items/page?id=…` | |
| Infuse | `infuse://series/<tmdbId>-<s>-<e>` | по TMDB-идентификатору сериала |
| Браузер | `https://jellyfin.example.com/web/#/details?id=…` | публичный адрес из `config.json → jellyfin_url` |

Обёртка открывает ссылки **только по строгому белому списку** схем/форматов —
произвольные URI не запускаются. Если подходящий клиент не установлен,
обёртка предложит установить его или открыть эпизод в браузере.

Новому пользователю: установите **популярный клиент из его апстрима**
(Findroid/Swiftfin/Fladder/Streamyfin), подключите в нём **свой** сервер
Jellyfin — deeplink заработает без дополнительной настройки на панели.

## Раздача сборок через панель (по желанию оператора)

Панель умеет раздачу ваших **собственных** артефактов (`/apps/`), но только
тех, что оператор явно перечислил в `config.json`:

```json
"mobile": {
  "dir": "/opt/dubs-mobile/releases",
  "artifacts": [ {"file": "dubs-1.2.apk", "label": "Android (собственная сборка)"} ]
}
```

Раздаются только файлы, реально присутствующие в каталоге `dir`; имена с
путями/точками отбрасываются — это белый список, не автоскан.

## Сборка из исходников

Gradle-wrapper в репозиторий не входит — используйте свой Gradle + Android SDK
(`compileSdk`/`targetSdk` 36, `minSdk` 28 = Android 9; TV-модуль — `mobile/android/tv`):

```bash
# Android (из каталога mobile/android):
gradle :app:assembleDebug        # телефон; :tv:assembleDebug — ТВ-вариант

# iOS (XcodeGen → проект Xcode):
cd mobile/ios && xcodegen && open Dubs.xcodeproj
```

В `mobile/tests` — вспомогательные скрипты разработки: smoke-проверки панели
(`panel-ui-smoke.cjs`, `tv-remote.cjs`, `tv-csp.cjs`, …), проверка
`ServerAddressTest.java`, сборочные помощники. Это инструменты локальной
разработки, а не поставляемые сборки.

Адрес панели вводится в самой обёртке («⚙ Сервер»), только HTTPS с
действительным сертификатом; смена сервера сбрасывает cookies и сессию.

## Метаданные файла и вид панели

Рядом с «В медиатеке» показывается качество **фактического файла**. Кнопка
раскрывает параметры видео и все аудиодорожки. Исходный тег каждой дорожки
показывается отдельно; неизвестная студия остаётся неизвестной. Данные
`unknown` и `stale` явно отмечаются, настройки желаемой загрузки их не заменяют.

В настройках есть переключатель «Показывать качество и озвучку»: по умолчанию
включён, сохраняется только на этом устройстве (`dubs-hide-media-details` в
localStorage). Выключение возвращает компактные строки без блоков метаданных,
сохраняя кнопки просмотра и загрузки. Работает в браузере и общей панели
Android/iOS/TV, управляется клавиатурой и пультом. Для этого переключателя
достаточно обновления панели, отдельная пересборка приложения не требуется.

## Локальные уведомления

Журнал доступен в «Настройки → События и уведомления». Типы событий,
аккаунтный выключатель и показ названий общие для аккаунта. Включение
уведомлений на конкретном устройстве и разрешение ОС задаются отдельно.
По умолчанию системное уведомление содержит только общее описание события;
адреса сервера, токены и ссылки плееров в системные данные не попадают.
Нажатие открывает соответствующую строку серии либо журнал, без автозагрузки.

* Браузер запрашивает разрешение только после нажатия пользователем и
  показывает уведомления, пока панель открыта. Приложения используют свой
  механизм, браузерный показ в них отключён.
* Android 9–16 и TV проверяют события при открытии приложения и через
  JobScheduler: период **от 15 минут**, ОС может задерживать запуск.
  Задание сохраняется через перезагрузку. Постоянного foreground service нет.
  При запрете приложения или канала интерфейс не сообщает об активной доставке.
  Представление уведомлений на TV зависит от производителя.
* iOS 17+ использует локальные уведомления и BGAppRefresh. Apple Developer
  и удалённая доставка не нужны. ОС может откладывать или пропускать фоновые
  проверки; после принудительного закрытия доставка не гарантируется.
  Истечение фонового времени отменяет сеть и завершает задачу один раз.

Регистрация выполняется после явного включения в авторизованной панели.
Устройство хранит отдельный токен только для чтения событий: Android Keystore
(AES-GCM), iOS Keychain с доступом приложения. При ошибке защищённого хранилища
включение отклоняется, записи токена открытым текстом нет. HTTPS обязателен,
перенаправления запросов ленты отвергаются, ответ ограничен 512 КБ/100 событий.
Отзыв токена останавливает проверки до повторной регистрации. Выключение
немедленно прекращает местную доставку; отзыв на сервере выполняется при
доступной сессии. Смена сервера сбрасывает регистрацию, задания и уведомления.
Новый идентификатор журнала (непрозрачная строка hex32) начинает новую эпоху,
старые уведомления и нажатия не переносятся.

## Совместимые сборки и проверка

Поставляемые значения: телефон/iOS 1.3.0 (13), TV 1.5.0-tv (8).
Общие идентификаторы по умолчанию — `app.dubs.panel` и `app.dubs.panel.tv`.
Для обновления существующей установки оператор должен сохранить её
applicationId/bundle ID и прежнюю подпись; менять их для обновления нельзя.
Сервер переносится из старых настроек `MainActivity`, WebView сохраняет
существующую авторизацию. Смена сервера по-прежнему требует входа.

Workflow `.github/workflows/mobile-release.yml` запускается вручную и
выдаёт только артефакты. Его inputs имеют приоритет над repository variables
`DUBS_ANDROID_APPLICATION_ID`, `DUBS_TV_APPLICATION_ID`, `DUBS_IOS_BUNDLE_ID`.
Телефонная Gradle-переменная `DUBS_APPLICATION_ID` получает значение первой
из этих repository variables. Для подписи используются только secrets
`DUBS_KEYSTORE_B64`, `DUBS_SIGNING_PASSWORD` и необязательный `DUBS_KEY_ALIAS`.
Ключи не входят в репозиторий. Без секретов выдаются отладочные APK.

iOS собирается для устройства без подписи и для симулятора. Для TrollStore
оператор подписывает устройство с entitlements конкретного bundle ID:
`application-identifier` и единственная `keychain-access-groups` должны
соответствовать приложению. Шаблон `Dubs.entitlements` использует значения
сборки; не подписывайте буквальные строки с `$()` и не добавляйте wildcard
доступа к Keychain. Артефакт workflow содержит разрешённый для TrollStore
plist с конкретным идентификатором. Удалённой доставки и её entitlement нет.

Проверки исходного текста и простой `javac` не заменяют сборку APK, lint,
эмулятор и Xcode. Workflow запускает Android instrumentation на API 28/36
(эмуляторы по 4 ГБ), реальные KeyStore/JobScheduler/WebView и тесты доставки,
дедупликации, приватности, запрета разрешения, эпохи и выключения. iOS
simulator tests проверяют реальный WK async API, состояние, смену эпохи,
однократное завершение/отмену при expiration и UI разрешения. Тестовые
подмены сети находятся только в тестовых targets, в release нет QA маршрутов.

Для браузерной проверки из любого каталога:

```bash
node /path/to/repo/mobile/tests/media-details-toggle.cjs
```

Нужны Python 3, Playwright и Chrome (`CHROME_PATH` для своего бинарника).
Тест рендерит реальный `render.py` с изолированными данными, проверяет исходные
аудиотеги, клавиатуру, скрытие/перезапуск/возврат метаданных и безопасный переход
к серии. Остальные `mobile/tests/*.cjs` читают исходники этого checkout,
не установленную панель. Результаты эмулятора/симулятора следует указывать
отдельно от локальных source/browser проверок.
