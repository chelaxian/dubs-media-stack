# Политики качества/озвучки и расписания

Факты ниже — из исходного кода (`src/episodes.py`, `src/upgrades.py`,
`installer/bootstrap.py`, `studios.json`) и юнит-тестов `tests/`. Состав и
границы тестов (юниты + реальный smoke-bootstrap) описаны в README
(«Статус и тесты») и [.github/workflows/ci.yml](../.github/workflows/ci.yml).

## Политика релизов (что считается допустимым)

Применяется в профилях Sonarr «Dubs RU 2160p» / «Dubs RU 1080p» (создаёт `bootstrap`):

1. **Русский язык обязателен.** Формат-veto (имя настраивается,
   по умолчанию «ОБЯЗАТЕЛЬНО RU — запрет без русского») срабатывает, когда в
   релизе нет ни русского аудио-маркера, ни русского языка метаданных;
   штраф −10 000 000 → релиз отбрасывается.
2. **Только 1080p и 2160p.** SD/480p/576p/720p запрещены (в группах качества
   профиля отмечены только 1080/2160; в 1080p-профиле — только 1080).
3. **Минимум 1 сид.** Установщик и синхронизация Jackett задают
   `minimumSeeders = 1` в управляемом профиле индексаторов «Dubs» в Prowlarr;
   панель также допускает раздачи с одним подтверждённым сидом. При равных
   качестве и озвучке выигрывает большее число сидов. Собственный профиль
   «Standard» оператору менять не требуется.
4. **Приоритет выбора**: качество (рейтинг позиции в профиле), затем **score
   форматов озвучки**, затем сиды. Ключевой score:

   | Формат | Очки |
   |---|---|
   | «Русская дорожка / RU» (маркер в названии) | +100 |
   | «Русская дорожка — язык метаданных» | +100 |
   | «Озвучка NN — <студия>» (именованная, по порядку studios.json) | 2^(12−index)·100 |
   | «Другая русская озвучка» (fallback, последняя запись) | 0 |
   | «Выбор сериала — <студия>» (при выборе в панели) | +1 000 000 |
   | veto (нет русского вообще) | −10 000 000 |

5. **Порог профиля** `minFormatScore = 100`: кандидату нужны доказательства
   русского (+100) или выбранная студия (+1 000 000).
6. **upgradeAllowed = false** в профилях: только ежедневный проход панели
   поднимает качество — случайные замены Sonarr'ом исключены.

`studios.json` — 14 записей: 13 именованных студий + «Другая русская озвучка»
(catch-all fallback; сама по себе доказательством RU не считается). Последняя
запись списка — всегда fallback; именованные — до неё.

## По-сериальные политики

В карточке сериала (вкладка «Озвучка») выбираются:

- **Студия озвучки** — предпочтение хранится по имени студии, так что
  перестановка записей в `studios.json` не перенаправляет выбор.
- **Режим**: `fallback` (по умолчанию — выбранная студия в приоритете, другие
  русские допустимы) или `strict` (если выбранной студии в кандидате нет —
  релиз отклоняется).

Дополнительно: заказ пачками (пачка сезона — строго по файлам сезона),
массовый заказ/отмена, отмена отдельного эпизода не трогает остальные.

## Ежедневный проход обновления качества

- **Когда**: ежедневно в `daily_upgrade_hour` (по умолчанию **18:00**) локальной
  зоны (`config.json → timezone`; смена пояса применяется на лету).
- **Что апгрейдится**: только **скачанные** эпизоды, которые в MyShows ещё
  **не просмотрены**. Просмотренное никогда не перекачивается.
- **Правило замены** (Парето-безопасность): кандидат улучшает **минимум одно**
  измерение и **не ухудшает ни одно** — голос не меняется на пиксели:
  ранг озвучки не падает, разрешение не падает.
- **Остановка**: достигнут 2160p **и** эффективная основная озвучка
  (выбранная для сериала, иначе top по умолчанию) — дальше не ищем.
- **Предыдущий файл сохраняется до валидного импорта** нового: замена происходит
  только после реального импорта в Sonarr (ранг кандидата сверяется с историей
  импорта конкретного файла).

## Мониторинг нового — без исторического бэклога

Импорт-лист «MyShows watching (Dubs feed)» в Sonarr настроен так
(`installer/bootstrap.py`, сверено с живой schema-API CustomImport):

- `shouldMonitor = future`, `monitorNewItems = all` — мониторятся **только
  будущие** эпизоды добавленных сериалов, а новые эпизоды уже добавленных —
  все;
- `searchForMissingEpisodes = false` — никакой массовой докачки истории;
- root folder `/tv`, папки сезонов включены, качество — профиль
  «Dubs RU 2160p».

Массовое добавление старых сезонов — всегда ручное решение оператора (панель,
bulk-заказ). Автоматизация `recent_episodes` ретраит **только** мониторимые,
вышедшие эпизоды за последние **48 часов**.

## Радarr и Lidarr

- **Radarr** получает ту же полную голосовую политику, что Sonarr: та же
  семья форматов озвучки с теми же очками, те же профили «Dubs RU 2160p/1080p»
  и RU-veto; каталог загрузок — `/downloads/complete/movies`.
- **Lidarr** — музыка через **API v1** и музыкальные профили качества/
  метаданных; сериальные голосовые форматы и RU-veto на него **не**
  распространяются. Каталог загрузок — `/downloads/complete/music`; root folder «Dubs Music»
  получает дефолты из существующих профилей (id из скелета не выдумывается:
  операторный `lidarr.json → quality_profile_id`/`metadata_profile_id` или
  первый валидный существующий профиль).
- Transmission использует отдельные каталоги: Sonarr — `/downloads/complete/tv`,
  Radarr — `/downloads/complete/movies`, Lidarr — `/downloads/complete/music`.
  Category пустая: API не допускает её совместно с Directory. Раздельные каталоги
  сохраняют изоляцию очередей и типов медиа; mapping `/downloads/ → /torrents/`
  остаётся общим для каждого приложения.

## Расписания (systemd)

Юниты рендерятся в `/etc/systemd/system` командой `install` (enable, старт —
вручную после настройки; см. [installation.md](installation.md)):

| Юнит | Период | Что делает |
|---|---|---|
| `dubs-panel@main` | демон | веб-роль панели (порт 9192/9193) |
| `dubs-worker@main` | демон | единственная роль с правом записи в медиа (очистка просмотренных) |
| `dubs-operations@main` | демон | ретраи/мониторинг эпизодов через Sonarr/Transmission |
| `dubs-myshows-feed` | демон, обновление ежечасно | фид «смотрю» для Custom List Sonarr, порт 9191 |
| `dubs-recovery.timer` | каждые 10 мин | восстановление зависших загрузок (только активные задания, данные не удаляет) |
| `dubs-recent-episodes.timer` | каждые 30 мин | ретраи вышедших за 48 ч эпизодов |
| `dubs-jackett-sync.timer` | каждые 6 ч | синхронизация индексаторов Jackett → Prowlarr (только профиль extras) |

По умолчанию ежедневный 18:00-проход выполняется внутри ролей панели по своему состоянию
(`src/upgrades.py`), не отдельным таймером.

## Очистка просмотренных файлов

- **Явный opt-in**: переключатель «Удалять просмотренные» в Настройках.
  Общая политика аккаунта сохраняется в `watch-settings.json`; до первого сохранения
  используется `cleanup_enable` из конфигурации (на свежих установках выключен).
  Отключение блокирует удаление медиатеки и повторные попытки очистки исходников;
  сохранение ждёт завершения уже начатой операции удаления.
- «Подтверждать отметку Просмотрено» включает диалог перед одиночной и массовой
  отметкой. Отмена диалога ничего не отправляет в MyShows.
- Перед первым включением: сначала **dry-preview** и **бэкап**
  (`python3 -m installer backup --dest ...`), затем включение.
- Воркер отказывается работать без готового хранилища (`storage_ready`:
  монтирование + sentinel).
- Просмотренное не перекачивается: отметки «просмотрено» из MyShows
  участвуют и в политике апгрейдов, и в очистке.
- Удаление — только файлов зарегистрированных импортов Sonarr, только ролью
  `worker` (единственная с правом записи в медиа-каталоги).

## Доказательства

Соответствие политик покрыто unittest-набором `tests/` (stdlib unittest,
без тяжёлых зависимостей): `test_upgrades.py`, `test_episodes.py`,
`test_bulk.py`, `test_season_batch.py`, `test_cleanup.py`,
`test_progress_actions.py`, `test_recovery.py`, `test_security.py`,
`test_players.py`, `test_search_fixes.py`, `test_render_runtime.py`.
Запуск в окружении тестов — через `tests/_dubs_env.py`. Систематический
прогон и статусы будут видны в CI; в этой документации счётчики тестов
сознательно не приводятся.

В Настройках → Расписание можно менять интервал MyShows (5–1440 минут),
время проверки улучшений и период (1–168 часов). Все роли читают
`schedule-settings.json` без перезапуска. Проверяются также одиночные заказы;
проверенные аудиодорожки имеют приоритет над рекламным названием раздачи.

## Автоматическое объединение трекеров

`src/tracker_merge.py` запускается фоновым потоком существующего worker операций;
отдельного systemd-таймера нет. При установке `src/` целиком копируется в каталог
приложения, поэтому функция включается также на новой установке.

- Каждый проход выбирает один публичный торрент Transmission, включая добавленные
  вручную, завершённые и приостановленные. Активные загрузки проверяются первыми.
- Проверка начинается спустя минуту после старта worker; следующие проходы —
  не чаще раза в минуту, без наложения. Один торрент повторно проверяется через
  шесть часов; после общего сбоя источников — примерно через час.
- Поиск идёт через включённые индексаторы Prowlarr. Torrent/magnet загружаются
  только через доверенные локальные шлюзы индексаторов.
- Совпадение проверяется по точному infohash: у torrent-файла хешируется исходное
  bencoded-поле `info`, у magnet используется `btih`. Совпадение имён не достаточно.
- Приватные торренты и источники с `private=1` исключены. Принимаются адреса
  только с разрешённых имён в `TRACKER_DOMAINS`; локальные адреса и URL с userinfo
  не допускаются. Список сознательно ограничен и может расширяться после проверки.
- За проход обрабатываются до 40 индексаторов, до 12 torrent/magnet-кандидатов,
  добавляются до 40 новых адресов. Поэтому проверка не гарантирует исчерпывающего
  охвата всех результатов поиска.
- Уже добавленные адреса не дублируются; выбор файлов, пауза и запуск не меняются.
  Для работающего торрента отправляется повторный announce.
- Последние проверки хранятся в `worker_state/tracker-merge.json` (0600), в журнал
  выводится только количество добавленных адресов. URL с ключами трекеров не логируются.

Проверки: `python3 -m unittest discover -s tests -p 'test_tracker_merge.py'`.
Практический разбор сети: [torrent-diagnostics.md](torrent-diagnostics.md).
